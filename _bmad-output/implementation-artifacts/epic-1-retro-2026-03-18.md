## Éxitos

1. **Ejecución impecable** — 10/10 stories, 67/67 ACs, 0 incidentes. Fundación sólida para los 4 epics siguientes.
2. **Zod schemas como fuente única de verdad (Story 1.4)** — `z.infer<>` elimina interfaces manuales. Un solo lugar define la forma de datos para validación, tests y UI.
3. **Arquitectura Astro static + Svelte islands (Story 1.7)** — Componentes estáticos con 0 JS al browser; interactividad selectiva con Svelte. Separación limpia.
4. **i18n nativo de Astro sin dependencias externas (Story 1.8)** — Routing basado en carpetas, sin librería de terceros. Menos complejidad, menos bundle.
5. **Prevención de FOUC con inline scripts (Story 1.9)** — Script síncrono en `<head>` lee localStorage antes del primer render. Tema persiste sin flash.
6. **Code review como red de seguridad** — 54 patches capturados antes de producción. Incluye accesibilidad (focus traps, aria-labels), validaciones Zod, y correcciones de spec.
7. **Tests progresivos con patrón de factories (Story 1.2)** — `crypto.randomUUID()` para datos deterministas y únicos. Reutilizable en todo el proyecto.
8. **CSS Variables + Tailwind v4 bridge (Story 1.5)** — `@theme inline` con custom properties habilita dark/light mode con pura manipulación DOM.

## Desafíos

1. **Bad Spec por research desactualizado (Stories 1.3, 1.7, 1.8)** — 3 de 10 stories tenían instrucciones basadas en Astro 5 o comportamiento incorrecto del framework. Ejemplos: `redirectToDefaultLocale: true` incompatible con `prefixDefaultLocale: false`, `position: fixed` cuando `sticky` era lo correcto.
2. **CI/CD no verificado consistentemente** — Christopher tuvo que recordar al equipo múltiples veces que verificaran el pipeline. La verificación no era parte explícita del Definition of Done.
3. **ESLint parcheado incrementalmente (Stories 1.1, 1.3, 1.7)** — En vez de configurar ESLint completamente en la Story 1.1, se fue parcheando: plugins no instalados, parser de Svelte faltante, archivos `.cjs` no reconocidos.
4. **TypeScript strictest mode friction (Stories 1.1, 1.2, 1.4, 1.6)** — Non-null assertions, `exactOptionalPropertyTypes`, type narrowing constante. Ralentizó el desarrollo pero atrapó errores reales.
5. **Validaciones faltantes descubiertas en code review (Stories 1.4, 1.6)** — `.refine()` para date ranges, discriminated unions, format validation en slugs, strings vacías en arrays. 9 patches solo en Story 1.4.
6. **Playwright configurado pero sin uso** — Infraestructura lista desde Story 1.2 pero sin un solo test E2E en todo el epic. Faltó plan explícito de cuándo entra.

---

## Insights Clave

1. **El research pre-spec debe validarse contra la documentación de la versión exacta del framework.** Las specs basadas en versiones anteriores causan re-trabajo significativo (30% de stories afectadas).
2. **La verificación del CI/CD debe ser parte del Definition of Done.** No es opcional. El pipeline existe para proteger, pero solo funciona si se verifica.
3. **Resolver tooling completamente al inicio del epic, no incrementalmente.** Cada parche de ESLint en una story posterior fue tiempo perdido que debió resolverse una vez.
4. **El code review es la inversión más valiosa del equipo.** 54 problemas capturados = 54 bugs potenciales evitados. Mantener siempre.
5. **Playwright debe tener plan de uso explícito.** Configurar sin usar genera incertidumbre. Definir en qué stories se aplica desde la planificación.
