## Desafíos

### 1. Contraste de Colores Sistémicamente Insuficiente

**Severidad: ALTA** — Descubierto en Story 5-5.

- axe-core detectó que `text-primary` (#48A1CD), `text-muted` (#8B95A5), y `bg-primary text-white` fallaban WCAG AA (4.5:1) en light mode
- Dark mode `text-muted` (#5A6270) también fallaba (2.67:1 vs necesario 4.5:1)
- Colores venían del diseño Flutter original — pasaron 4 epics sin detectarse

**Root cause:** No había herramienta de auditoría de accesibilidad (axe-core) integrada en el pipeline. Los contrast tests existentes verificaban valores hardcodeados, no el ratio real contra fondos.

**Fix:** Variables CSS theme-aware con valores diferentes para light/dark. Light mode usa tonos más oscuros, dark mode tonos más claros. Tests de contraste actualizados para verificar ambos modos.

### 2. Gaps en Specs de Stories

**Severidad: MEDIA** — Apareció en 2 de 6 stories (5-3, 5-4).

- Story 5-4: Spec omitió `ProjectFilter.svelte` de la lista de componentes a optimizar (CLS). Spec indicó agregar `crossorigin` al preconnect, lo cual era incorrecto.
- Story 5-3: Code review F1 notó que unit tests verifican mock wiring, no comportamiento real (mismo patrón que Epic 4).

**Root cause:** SM crea specs basándose en documentación pero ocasionalmente omite componentes o asume APIs incorrectamente sin verificar contra el código real.

### 3. E2E Contra Producción (No Emuladores)

**Severidad: BAJA** (proyecto terminado) — Presente todo el epic.

- Story 5-2 encontró 20 documentos huérfanos de E2E en producción Firestore
- Scripts de cleanup creados como parche, globalTeardown como safety net
- Emuladores configurados pero E2E nunca migrados

**Root cause:** Complejidad de configurar emuladores con Auth + Firestore + Storage juntos. Siempre hubo prioridades más urgentes.

**Mitigación:** Scripts de cleanup automáticos resuelven el síntoma. Como el proyecto está terminado, no se justifica la inversión de migrar a emuladores.

### 4. Lighthouse CI No Verificado Localmente

**Severidad: BAJA** — Story 5-4.

- Optimizaciones de performance implementadas sin verificación local de Lighthouse
- CI/CD sí ejecuta Lighthouse en cada push (no se saltó nunca)
- No hubo problema real porque las optimizaciones son recomendaciones estándar

**Root cause:** Lighthouse local requiere Chrome headless + servidor preview — setup que el dev no ejecutó durante la sesión.
